# Правила разработки «Моего гаража»

## Структура

- `src/main.ts` запускает приложение; `src/App.vue` содержит оболочку и навигацию.
- `views/` — экраны; `components/` — отдельные UI-блоки. Компоненты передают действия через типизированные события, а данные получают через props.
- Каждой сущности — свой Pinia-стор и каталог `stores/<entity>/`. Определяй стор в `<entity>.ts`; типы, чистые функции и адаптеры держи рядом, добавляя файлы по необходимости. Не размещай одну сущность внутри каталога другой.
- `stores/garage/` владеет профилями, записями и сохранением через `localStorage`. `stores/demo/` создаёт исходный демо-профиль, но не хранит его копию: после добавления профиль принадлежит гаражу. Сторы взаимодействуют через публичный интерфейс; адаптер хранения не обращается к Pinia напрямую.
- Читай общее реактивное состояние через `storeToRefs()` и меняй его через действия стора. Не создавай циклических зависимостей между сторами.
- `composables/` — логика интерфейса, например состояние формы и форматирование. Не дублируй данные стора.
- `plugins/` — подключение библиотек, `lang/` — словари интерфейса, `assets/` — стили. Не добавляй инфраструктуру, которую приложение не использует.

## Vue, TypeScript и UI

- Любые импорты файлов из `src` оформляй через `@/`, без относительных путей; внешние пакеты импортируй по имени.
- В Vue-компонентах разделяй импорты одной пустой строкой: (1) Vue, Pinia, i18n, сторы и прочая логика/типы; (2) компоненты PrimeVue; (3) локальные `.vue`-компоненты. Пустые блоки пропускай.
- Объявляй функции через `const name = (...) => ...`, в том числе экспортируемые функции и composables. Для Vue используй `<script setup lang="ts">`, типизированные props и emits, а для импортов типов — `import type`.
- Пользовательские подписи, подсказки, ошибки и доступные имена храни в словаре. В компонентах используй `useI18n()`; форматирование дат, денег и единиц — через `useGarageFormat()`. Не используй перевод в качестве значения сохраняемого поля.
- Используй PrimeVue в режиме `unstyled` и PrimeIcons. Сохраняй видимый фокус, текстовые подписи основных действий и доступные имена кнопок без текста. На главной оставляй краткий обзор; историю и статистику размещай в журнале. Не полагайся на цвет или иконку как единственную подпись.

## Сохранённые данные

- Ключ `moy-garazh:auto:garage` и схема версии `1` — контракт с существующими данными. Суммы хранятся в целых копейках, даты — в формате `YYYY-MM-DD`, пробег — в километрах. Не меняй значения категорий или схему без продуманной миграции.
- Не перезаписывай данные при ошибке чтения или обнаруженном конфликте с другой вкладкой. Хранилище возвращает коды ошибок, а пользовательские сообщения переводятся в интерфейсе.
- Не смешивай записи разных профилей. Сохраняй CRUD пользовательских полей, трат, заправок и замен масла, а также расчёт расхода по полным заправкам.
